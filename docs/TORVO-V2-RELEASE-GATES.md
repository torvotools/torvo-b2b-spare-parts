# TORVO V2 RELEASE GATES

## SOURCE GATE
- RELEASE SOURCE IS `torvo-v2-build` ONLY.
- EXACT RELEASE SHA MUST PASS BUILD CHECK AND CLOUDFLARE PREVIEW.
- V27 / MAIN IS NOT A RELEASE SOURCE FOR V2.

## DEALER SECURITY GATE
- ONE DEALER ACCOUNT = ONE ACTIVE MOBILE DEVICE SESSION.
- REVOKED OLD DEVICE MUST FAIL PRIVATE CATALOG, RATE, PURCHASE ORDER, ORDER HISTORY, CONFIRMATION, MACHINE SPARES, FITMENT, REFERRAL AND MISSING-PART ACTIONS.
- PRIVATE DEALER CATALOG AND 30-DAY ORDER HISTORY MUST BOTH PASS THROUGH DEVICE-BOUND WORKSPACE RPCS; THE DEALER PORTAL MUST NOT READ THEM THROUGH THE GENERIC REPOSITORY.
- LEGACY NO-DEVICE RPC SIGNATURES MUST BE ABSENT AFTER FINAL DEVICE-BOUND MIGRATIONS.
- LEGACY UI COMPATIBILITY MAY EXIST ONLY AS A BRIDGE TO THE CURRENT DEVICE-BOUND SERVICES; IT MUST NEVER CALL PRIVATE DEALER TABLES OR RETIRED RPC SIGNATURES DIRECTLY.
- DEAD GENERIC LEGACY METHODS ARE NOT A VALID DEALER PATH: DEALER UI MUST IMPORT THE SECURE BRIDGE AND SERVER EXECUTE PRIVILEGES FOR RETIRED SIGNATURES MUST REMAIN REVOKED.
- DEALER LOGIN USES +91 / 10-DIGIT MOBILE IDENTITY; APP ENTRY MUST ALSO OFFER REGISTER AS DEALER.

## STAFF ACCESS GATE
- STAFF LOGIN USES ADMIN-ISSUED STAFF USER ID + ONE-TIME PASSWORD; STAFF IS NOT FORCED TO USE A MOBILE NUMBER AS USERNAME.
- SALESMAN ATTENDANCE IS SERVER-IDENTITY BOUND: ONE CHECK-IN PER DATE, CHECK-OUT ONLY AFTER CHECK-IN, SELF HISTORY FOR SALESMAN, OWNER/ADMIN REPORTING AND STATUS CONTROL.
- STAFF DEVICE/ROLE AUTHORIZATION REMAINS SERVER-SIDE; CLIENT-SUPPLIED ROLE IS NEVER AUTHORITATIVE.

## STAGING GATE
- APPLY `supabase/V2_INSTALL_ORDER.md` IN ORDER TO A DEDICATED V2 STAGING DATABASE.
- BUILD PREFLIGHT MUST VERIFY CRITICAL MIGRATIONS EXIST AND AUTH/DEVICE/ATTENDANCE/RELEASE DEPENDENCY ORDER HAS NOT DRIFTED.
- STOP ON FIRST SQL ERROR; DO NOT SKIP A FAILED MIGRATION.
- RUN `supabase/tests/v2-dealer-auth-security-checklist.sql` AND ROLE/PRIVACY CHECKS.
- DEPLOY AUTH EDGE FUNCTIONS WITH SERVER-ONLY SERVICE ROLE SECRET.

## BUSINESS LOGIC GATE
- APPROVED TORVO V2 BUSINESS RULES MUST REMAIN ACTIVE THROUGH WEB, APP, ADMIN AND DATABASE FLOWS; A UI BUTTON MUST NOT BYPASS, REPLACE OR SILENTLY DISABLE THE AUTHORITATIVE SERVER LOGIC.
- DEALER OK IS REVISION-SPECIFIC; A NEW TORVO REVISION INVALIDATES THE PREVIOUS APPROVAL REQUIREMENT.
- ADD MORE ITEMS CREATES A SEPARATE LINKED ADDITIONAL ORDER ONLY AFTER THE APPROVED REQUEST; IT MUST NOT MUTATE THE ORIGINAL ORDER/ESTIMATE.
- DEALER RATE, QUANTITY, DUPLICATE-LINE, DEVICE, ROLE AND ORDER-ownership VALIDATION MUST REMAIN SERVER-AUTHORITATIVE EVEN WHEN CLIENT VALIDATION ALSO EXISTS.
- PUBLIC CUSTOMER HAS NO TORVO RETAIL CHECKOUT OR PUBLIC SELLING PRICE.
- DEALER B2B RATE/ORDER FLOW REMAINS PRIVATE.
- PURCHASE, PAYMENT, DELIVERY, INVENTORY AND RETURN INTEGRITY MUST PASS END-TO-END STAGING TESTS.

## APP / WEB GATE
- WEBSITE AND APP MUST USE THE SAME AUTHORITATIVE BACKEND.
- ANDROID DEBUG APK IS TEST ONLY.
- PRODUCTION ANDROID REQUIRES PRIVATE SIGNING + SIGNED AAB/APK + REAL DEVICE TEST.
- IOS REQUIRES APPLE DEVELOPER/XCODE/TESTFLIGHT RELEASE INFRASTRUCTURE.

## LIVE GATE
- DO NOT SWITCH `torvotools.com` UNTIL STAGING, EXACT SHA PREVIEW, BACKUP/RESTORE AND OWNER ACCEPTANCE PASS.
- EXTERNAL CREDENTIALS (WHATSAPP, SIGNING, APP STORES, DOMAIN/DNS) ARE FINAL DEPLOYMENT DEPENDENCIES, NOT SOURCE-CODE COMPLETION CLAIMS.
