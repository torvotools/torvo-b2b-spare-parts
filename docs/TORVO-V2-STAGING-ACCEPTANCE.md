# TORVO V2 STAGING ACCEPTANCE

This is the final runtime acceptance matrix before production/domain switch.

1. APPLY EVERY SQL FILE ONLY IN `supabase/V2_INSTALL_ORDER.md` ORDER. STOP AT FIRST ERROR.
2. DEPLOY DEALER PIN LOGIN, DEALER SESSION VALID, DEALER SESSION REVOKE AND STAFF ONE-TIME LOGIN EDGE FUNCTIONS.
3. DEVICE TEST: LOGIN DEALER ON MOBILE A, THEN MOBILE B. MOBILE B MUST WORK AND MOBILE A MUST FAIL EVERY PRIVATE READ/WRITE, INCLUDING PRIVATE CATALOG AND 30-DAY ORDER HISTORY.
4. DEALER READ BOUNDARY TEST: WITH DEVICE B ACTIVE, PRIVATE CATALOG AND 30-DAY SALES ORDER/ESTIMATE HISTORY MUST LOAD. REVOKE DEVICE B AND REPEAT THE SAME CALLS; BOTH MUST FAIL. HISTORY MUST CONTAIN ONLY THE ASSERTED DEALER AND ONLY THE LAST 30 DAYS.
5. DEALER APP-ONLY TEST: DEALER MOBILE + PIN LOGIN MUST BE AVAILABLE IN THE NATIVE TORVO TOOLS APP. OPEN THE SAME PRIVATE LOGIN ON NORMAL WEB/DOMAIN: DEALER LOGIN OPTION MUST NOT BE OFFERED. IF A DEALER WEB SESSION ALREADY EXISTS, `/v2.html` MUST REFUSE THE PRIVATE DEALER WORKSPACE. PUBLIC DEALER REGISTRATION/DISCOVERY ON THE WEBSITE REMAINS AVAILABLE.
6. FINAL ACCESS ROUTING: ONE TORVO NATIVE APP SERVES DEALER, SALESMAN AND STORE KEEPER ONLY; THEIR ROLE SELECTS THE AUTHORIZED WORKSPACE. NORMAL WEBSITE HAS ONE SMALL `BUSINESS USE` ENTRY FOR OWNER/ADMIN/ACCOUNTANT STAFF LOGIN; THERE MUST NOT BE SEPARATE ADMIN AND ACCOUNTANT LOGIN BUTTONS. USER ID ROLE IS DETECTED SERVER-SIDE/SESSION-SIDE AND THE USER MUST NEVER CHOOSE OR IMPERSONATE A ROLE.
7. WRONG-RUNTIME TEST: DEALER/SALESMAN/STORE KEEPER MUST BE REJECTED AND SIGNED OUT ON NORMAL WEB PRIVATE ACCESS. OWNER/ADMIN/ACCOUNTANT MUST BE REJECTED FROM THE NATIVE OPERATIONAL APP. ADMIN MAY USE LIMITED MOBILE-WEB FOR REPORTS, APPROVALS AND USER/PASSWORD EMERGENCY ACTIONS. ACCOUNTANT HAS NO NATIVE APP AND MAY USE SECURE BUSINESS USE WEB ACCESS.
8. LOGIN ENTRY TEST: DEALER USES +91 / 10-DIGIT MOBILE LOGIN AND CAN OPEN REGISTER AS DEALER FROM THE APP. STAFF USES STAFF USER ID + SERVER-GENERATED MASTER-EMAIL OTP; STAFF USER ID MUST NOT BE FORCED INTO A MOBILE-NUMBER FIELD. THE PUBLIC MOBILE ROUTER MUST RETURN `dealer_pin` ONLY FOR ONE ACTIVE DEALER AND MUST NEVER ROUTE STAFF TO THE RETIRED STAFF WHATSAPP OTP OR PASSWORD PATH.
9. STAFF DEVICE TEST: ACCOUNTANT/ADMIN LOGIN MUST FAIL ON `mobile_app`; SALESMAN/STORE KEEPER LOGIN MUST FAIL ON `desktop`; ONLY THE OWNER/ADMIN-APPROVED ACTIVE DEVICE/INSTALLATION MAY REQUEST AND VERIFY A VALID MASTER-EMAIL OTP. NATIVE APP REINSTALL MUST CREATE A NEW INSTALLATION ID AND REQUIRE NEW APPROVAL + OTP.
10. STAFF OTP TEST: A SERVER-GENERATED 6-DIGIT OTP MUST GO ONLY TO THE SINGLE OWNER/ADMIN-CONTROLLED MASTER OTP EMAIL, IDENTIFY THE REQUESTING STAFF USER/ROLE/CONTEXT, EXPIRE IN 10 MINUTES, BE SINGLE-USE, RESPECT RESEND THROTTLING, AND FAIL ON REUSE/REVOKE/EXPIRY. LEGACY ADMIN-ISSUED STAFF PASSWORD OBJECTS MUST REMAIN ABSENT/RETIRED.
11. WHATSAPP ROUTING: PUBLIC CUSTOMER EXPERIENCE USES CUSTOMER WHATSAPP. DEALER/SALESMAN/STORE KEEPER USE BUSINESS WHATSAPP. OWNER/ADMIN/ACCOUNTANT CAN OPEN BOTH CUSTOMER AND BUSINESS WHATSAPP. BOTH NUMBERS DEFAULT TO 7027751533 UNTIL ADMIN CHANGES THEM; ADMIN CAN CHANGE OR DISABLE EACH CHANNEL WITHOUT CODE DEPLOYMENT.
12. SALESMAN ATTENDANCE TEST: SALESMAN CAN CHECK IN ONLY ONCE PER DAY, CANNOT CHECK OUT BEFORE CHECK IN, CAN VIEW OWN HISTORY, AND OWNER/ADMIN CAN VIEW DATE-RANGE ATTENDANCE AND CHANGE ATTENDANCE STATUS. OTHER ROLES MUST FAIL ADMIN ATTENDANCE RPCS. VERIFY THE REPORT RETURNS THE CORRECT SALESMAN NAME FROM THE INSTALLED `app_users` SCHEMA.
13. DEALER FLOW: SEARCH → RATE → PURCHASE ORDER → TORVO SALES ORDER/REVISION → DEALER OK → ESTIMATE → PAYMENT/FULFILMENT → DELIVERY.
14. DEALER OK TEST: `REVIEW & GIVE DEALER OK` MUST OPEN THE EXACT CURRENT REVISION, `GIVE DEALER OK` MUST SUBMIT THAT REVISION THROUGH THE DEVICE-BOUND CONFIRMATION RPC, AND A LATER TORVO REVISION MUST REQUIRE A NEW DEALER OK.
15. ADD MORE ITEMS TEST: DEALER SENDS `ADD MORE ITEMS` REQUEST WITH A VALID REASON → TORVO APPROVES → APPROVED REQUEST APPEARS TO THAT SAME DEALER → DEALER SELECTS ITEMS/QUANTITIES → SERVER RECALCULATES CURRENT DEALER RATES → `CONFIRM NEW ORDER` CREATES ONE NEW LINKED ADDITIONAL ORDER. THE ORIGINAL ORDER/ESTIMATE MUST REMAIN UNCHANGED AND AN ALREADY-CONSUMED APPROVAL MUST NOT CREATE A SECOND ORDER.
16. PUBLIC FLOW: PRODUCT SEARCH → NEARBY DEALER → CUSTOMER REQUIREMENT. NO PUBLIC TORVO SELLING PRICE OR CHECKOUT.
17. INVENTORY FLOW: PURCHASE RECEIPT POSTS STOCK ONCE; FULFILMENT/DELIVERY DEDUCTS ONLY ONCE; REVERSAL IS AUDITED.
18. ROLE TEST: OWNER, ADMIN, ACCOUNTANT, SALESMAN, STORE KEEPER AND DEALER MUST SEE ONLY AUTHORIZED DATA/ACTIONS.
19. RELEASE CENTER: UNVERIFIED/DEBUG/VERIFIED_TEST ARTIFACT MUST NOT APPEAR AS PRODUCTION UPDATE. PRODUCTION RELEASE RECORDS REQUIRE VERIFIED/PUBLISHED STATUS FROM A TRUSTED RELEASE WRITER.
20. BACKUP/RESTORE: CREATE BACKUP, VERIFY MANIFEST/INTEGRITY, RESTORE TO STAGING, VERIFY CORE COUNTS.
21. MOBILE + DESKTOP: NO BLOCKING BROWSER ALERT/CONFIRM UX, NO HORIZONTAL OVERFLOW, CORE BUTTONS COMPLETE. SEARCH MUST KEEP CAMERA BEFORE MIC, MIC LAST AMONG INPUT TOOLS, NO `ALL` FILTER, AND AS-YOU-TYPE GROUPED SUGGESTIONS WITHOUT A HEAVY BORDERED DROPDOWN.
22. ANDROID TEST: USE THE DURABLE OWNER/ADMIN TEST URL `https://github.com/torvotools/torvo-b2b-spare-parts/releases/download/torvo-v2-test-latest/TORVO-TOOLS-TEST-latest.apk`. VERIFY THE RELEASE IS A GITHUB PRERELEASE, PACKAGE IS `com.torvotools.app`, MANIFEST SHA256 MATCHES THE APK, AND RELEASE COMMIT MATCHES THE BUILD UNDER REVIEW.
23. REAL DEVICE REVIEW: INSTALL/UPDATE THE EXACT-SHA `TEST-DEBUG` APK ON A REAL ANDROID DEVICE; OPEN APP, CHECK MOBILE UI/BUTTONS, DEALER/STAFF LOGIN, REGISTRATION, LOGIN/LOGOUT/REVOKE, SALESMAN ATTENDANCE, SEARCH, PURCHASE ORDER, DEALER OK, ADD MORE ITEMS AND DELIVERY FLOWS. RECORD SCREENSHOTS, APK SHA256 AND BUILD SHA. EACH UI/LOGIC ISSUE RETURNS TO `torvo-v2-build` FOR A NEW TEST BUILD.
24. ANDROID PRODUCTION: DEBUG OR `VERIFIED_TEST` APK IS NEVER A PLAY STORE RELEASE. PRODUCTION REQUIRES PRIVATE SIGNING, RELEASE BUILD, SIGNED AAB/APK, VERSION/BUILD NUMBER AND OWNER ACCEPTANCE. THE SAME PRODUCTION SIGNING IDENTITY MUST BE PRESERVED FOR UPDATE CONTINUITY.
25. APP UPDATE RULE: DATA/CONTENT/RATES/STOCK/COMPATIBILITY UPDATE FROM THE CENTRAL BACKEND WITHOUT REINSTALL. NATIVE PROGRAM/CODE CHANGES REQUIRE A NEW SIGNED APP RELEASE. DIRECT APK UPDATES REQUIRE ANDROID USER APPROVAL; DO NOT CLAIM SILENT INSTALL.
26. PRODUCTION UPDATE SAFETY: PUBLIC UPDATE METADATA MUST NEVER RETURN THE DURABLE TEST APK URL. ONLY PUBLISHED, PRODUCTION-SIGNED, DURABLE HTTPS ANDROID RELEASES FOR PACKAGE `com.torvotools.app` MAY SHOW `UPDATE AVAILABLE` / `UPDATE REQUIRED` TO NORMAL USERS.
27. EXACT SHA: BUILD CHECK, WEB PREVIEW AND TEST APK MUST MATCH THE ACCEPTED RELEASE SHA BEFORE PRODUCTION PROMOTION.

External gates: WhatsApp provider credentials, Android signing/Play Console, Apple Developer/TestFlight/App Store, production Supabase credentials and final DNS/domain change.
