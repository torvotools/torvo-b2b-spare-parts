# TORVO V2 STAGING ACCEPTANCE

This is the final runtime acceptance matrix before production/domain switch.

1. APPLY EVERY SQL FILE ONLY IN `supabase/V2_INSTALL_ORDER.md` ORDER. STOP AT FIRST ERROR.
2. DEPLOY DEALER PIN LOGIN, DEALER SESSION VALID, DEALER SESSION REVOKE AND STAFF ONE-TIME LOGIN EDGE FUNCTIONS.
3. DEVICE TEST: LOGIN DEALER ON MOBILE A, THEN MOBILE B. MOBILE B MUST WORK AND MOBILE A MUST FAIL EVERY PRIVATE READ/WRITE.
4. DEALER FLOW: SEARCH → RATE → PURCHASE ORDER → TORVO SALES ORDER/REVISION → DEALER OK → ESTIMATE → PAYMENT/FULFILMENT → DELIVERY.
5. PUBLIC FLOW: PRODUCT SEARCH → NEARBY DEALER → CUSTOMER REQUIREMENT. NO PUBLIC TORVO SELLING PRICE OR CHECKOUT.
6. INVENTORY FLOW: PURCHASE RECEIPT POSTS STOCK ONCE; FULFILMENT/DELIVERY DEDUCTS ONLY ONCE; REVERSAL IS AUDITED.
7. ROLE TEST: OWNER, ADMIN, ACCOUNTANT, SALESMAN, STORE KEEPER AND DEALER MUST SEE ONLY AUTHORIZED DATA/ACTIONS.
8. RELEASE CENTER: UNVERIFIED/DEBUG ARTIFACT MUST NOT APPEAR AS PRODUCTION DOWNLOAD. VERIFIED/PUBLISHED ONLY.
9. BACKUP/RESTORE: CREATE BACKUP, VERIFY MANIFEST/INTEGRITY, RESTORE TO STAGING, VERIFY CORE COUNTS.
10. MOBILE + DESKTOP: NO BLOCKING BROWSER ALERT/CONFIRM UX, NO HORIZONTAL OVERFLOW, CORE BUTTONS COMPLETE.
11. ANDROID: INSTALL TEST APK ON REAL DEVICE; LOGIN/LOGOUT/REVOKE/ORDER FLOW MUST PASS. PRODUCTION NEEDS PRIVATE SIGNED AAB/APK.
12. EXACT SHA: BUILD CHECK AND PREVIEW MUST BOTH MATCH THE ACCEPTED RELEASE SHA BEFORE DOMAIN SWITCH.

External gates: WhatsApp provider credentials, Android signing/Play Console, Apple Developer/TestFlight/App Store, production Supabase credentials and final DNS/domain change.
