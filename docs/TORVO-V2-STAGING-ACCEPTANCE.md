# TORVO V2 STAGING ACCEPTANCE

This is the final runtime acceptance matrix before production/domain switch.

1. APPLY EVERY SQL FILE ONLY IN `supabase/V2_INSTALL_ORDER.md` ORDER. STOP AT FIRST ERROR.
2. DEPLOY DEALER PIN LOGIN, DEALER SESSION VALID, DEALER SESSION REVOKE AND STAFF ONE-TIME LOGIN EDGE FUNCTIONS.
3. DEVICE TEST: LOGIN DEALER ON MOBILE A, THEN MOBILE B. MOBILE B MUST WORK AND MOBILE A MUST FAIL EVERY PRIVATE READ/WRITE.
4. LOGIN ENTRY TEST: DEALER USES +91 / 10-DIGIT MOBILE LOGIN AND CAN OPEN REGISTER AS DEALER FROM THE APP. STAFF USES STAFF USER ID + ADMIN-ISSUED ONE-TIME PASSWORD; STAFF USER ID MUST NOT BE FORCED INTO A MOBILE-NUMBER FIELD. THE PUBLIC MOBILE ROUTER MUST RETURN `dealer_pin` ONLY FOR ONE ACTIVE DEALER AND MUST NEVER ROUTE STAFF TO THE RETIRED STAFF WHATSAPP OTP PATH.
5. STAFF DEVICE TEST: ACCOUNTANT LOGIN MUST FAIL ON `mobile_app`; SALESMAN/STORE KEEPER LOGIN MUST FAIL ON `desktop`; ONLY THE ADMIN-APPROVED ACTIVE DEVICE MAY CONSUME A VALID ONE-TIME PASSWORD.
6. STAFF PASSWORD TEST: A VALID ADMIN-ISSUED PASSWORD MUST BE HASHED, EXPIRE WITHIN THE ALLOWED WINDOW, BE CONSUMED ON FIRST SUCCESSFUL LOGIN AND FAIL ON REUSE/REVOKE/EXPIRY.
7. SALESMAN ATTENDANCE TEST: SALESMAN CAN CHECK IN ONLY ONCE PER DAY, CANNOT CHECK OUT BEFORE CHECK IN, CAN VIEW OWN HISTORY, AND OWNER/ADMIN CAN VIEW DATE-RANGE ATTENDANCE AND CHANGE ATTENDANCE STATUS. OTHER ROLES MUST FAIL ADMIN ATTENDANCE RPCS. VERIFY THE REPORT RETURNS THE CORRECT SALESMAN NAME FROM THE INSTALLED `app_users` SCHEMA.
8. DEALER FLOW: SEARCH → RATE → PURCHASE ORDER → TORVO SALES ORDER/REVISION → DEALER OK → ESTIMATE → PAYMENT/FULFILMENT → DELIVERY.
9. DEALER OK TEST: `REVIEW & GIVE DEALER OK` MUST OPEN THE EXACT CURRENT REVISION, `GIVE DEALER OK` MUST SUBMIT THAT REVISION THROUGH THE DEVICE-BOUND CONFIRMATION RPC, AND A LATER TORVO REVISION MUST REQUIRE A NEW DEALER OK.
10. ADD MORE ITEMS TEST: DEALER SENDS `ADD MORE ITEMS` REQUEST WITH A VALID REASON → TORVO APPROVES → APPROVED REQUEST APPEARS TO THAT SAME DEALER → DEALER SELECTS ITEMS/QUANTITIES → SERVER RECALCULATES CURRENT DEALER RATES → `CONFIRM NEW ORDER` CREATES ONE NEW LINKED ADDITIONAL ORDER. THE ORIGINAL ORDER/ESTIMATE MUST REMAIN UNCHANGED AND AN ALREADY-CONSUMED APPROVAL MUST NOT CREATE A SECOND ORDER.
11. PUBLIC FLOW: PRODUCT SEARCH → NEARBY DEALER → CUSTOMER REQUIREMENT. NO PUBLIC TORVO SELLING PRICE OR CHECKOUT.
12. INVENTORY FLOW: PURCHASE RECEIPT POSTS STOCK ONCE; FULFILMENT/DELIVERY DEDUCTS ONLY ONCE; REVERSAL IS AUDITED.
13. ROLE TEST: OWNER, ADMIN, ACCOUNTANT, SALESMAN, STORE KEEPER AND DEALER MUST SEE ONLY AUTHORIZED DATA/ACTIONS.
14. RELEASE CENTER: UNVERIFIED/DEBUG/VERIFIED_TEST ARTIFACT MUST NOT APPEAR AS PRODUCTION UPDATE. PRODUCTION RELEASE RECORDS REQUIRE VERIFIED/PUBLISHED STATUS FROM A TRUSTED RELEASE WRITER.
15. BACKUP/RESTORE: CREATE BACKUP, VERIFY MANIFEST/INTEGRITY, RESTORE TO STAGING, VERIFY CORE COUNTS.
16. MOBILE + DESKTOP: NO BLOCKING BROWSER ALERT/CONFIRM UX, NO HORIZONTAL OVERFLOW, CORE BUTTONS COMPLETE.
17. ANDROID TEST: USE THE DURABLE OWNER/ADMIN TEST URL `https://github.com/torvotools/torvo-b2b-spare-parts/releases/download/torvo-v2-test-latest/TORVO-TOOLS-TEST-latest.apk`. VERIFY THE RELEASE IS A GITHUB PRERELEASE, PACKAGE IS `com.torvotools.app`, MANIFEST SHA256 MATCHES THE APK, AND RELEASE COMMIT MATCHES THE BUILD UNDER REVIEW.
18. REAL DEVICE REVIEW: INSTALL/UPDATE THE EXACT-SHA `TEST-DEBUG` APK ON A REAL ANDROID DEVICE; OPEN APP, CHECK MOBILE UI/BUTTONS, DEALER/STAFF LOGIN, REGISTRATION, LOGIN/LOGOUT/REVOKE, SALESMAN ATTENDANCE, SEARCH, PURCHASE ORDER, DEALER OK, ADD MORE ITEMS AND DELIVERY FLOWS. RECORD SCREENSHOTS, APK SHA256 AND BUILD SHA. EACH UI/LOGIC ISSUE RETURNS TO `torvo-v2-build` FOR A NEW TEST BUILD.
19. ANDROID PRODUCTION: DEBUG OR `VERIFIED_TEST` APK IS NEVER A PLAY STORE RELEASE. PRODUCTION REQUIRES PRIVATE SIGNING, RELEASE BUILD, SIGNED AAB/APK, VERSION/BUILD NUMBER AND OWNER ACCEPTANCE. THE SAME PRODUCTION SIGNING IDENTITY MUST BE PRESERVED FOR UPDATE CONTINUITY.
20. APP UPDATE RULE: DATA/CONTENT/RATES/STOCK/COMPATIBILITY UPDATE FROM THE CENTRAL BACKEND WITHOUT REINSTALL. NATIVE PROGRAM/CODE CHANGES REQUIRE A NEW SIGNED APP RELEASE. DIRECT APK UPDATES REQUIRE ANDROID USER APPROVAL; DO NOT CLAIM SILENT INSTALL.
21. PRODUCTION UPDATE SAFETY: PUBLIC UPDATE METADATA MUST NEVER RETURN THE DURABLE TEST APK URL. ONLY PUBLISHED, PRODUCTION-SIGNED, DURABLE HTTPS ANDROID RELEASES FOR PACKAGE `com.torvotools.app` MAY SHOW `UPDATE AVAILABLE` / `UPDATE REQUIRED` TO NORMAL USERS.
22. EXACT SHA: BUILD CHECK, WEB PREVIEW AND TEST APK MUST MATCH THE ACCEPTED RELEASE SHA BEFORE PRODUCTION PROMOTION.

External gates: WhatsApp provider credentials, Android signing/Play Console, Apple Developer/TestFlight/App Store, production Supabase credentials and final DNS/domain change.
